## 1. 为什么编译器工程师要懂 NPU

### 1.1 问题

只盯着「图在数学上等价」不够：

- 同样正确的图，融不融合可能差 **数倍带宽**  
- 同样 MatMul，tile 不对就吃不满 Cube  
- DMA 与计算不同时重叠，算力在空等数据  

### 1.2 效果

懂硬件 → 能预测「该融、该切、该量化」；能读懂 profiling。  
不懂 → 只会重试 ATC 参数碰运气。

## 2. 逻辑结构（概念实现）

### 2.1 总览

```text
主机 CPU（控制、部分预处理）
        │ PCIe / 系统总线
        ▼
昇腾设备
  ├─ AI Core × N
  │    ├─ Cube     ：稠密矩阵类（Conv/GEMM 主力）
  │    ├─ Vector   ：向量/激活/归一化等
  │    ├─ Scalar   ：控制与小规模标量
  │    └─ 片上缓冲 ：如 UB 等（名称随代际变）
  ├─ AI CPU        ：不适合 AI Core 的算子、部分控制
  ├─ DMA / 搬运引擎：DDR/HBM ↔ 片上
  └─ 片外大内存
```

### 2.2 为什么拆 Cube / Vector / AI CPU

| 单元 | 为什么存在 | 编译器映射时想什么 |
|---|---|---|
| Cube | 矩阵吞吐是卖点 | 这个 op 能不能变成 GEMM/Conv 形态 |
| Vector | 很多激活不是矩阵 | Softmax、Layernorm 落哪 |
| AI CPU | 长尾、控制、暂无 Core 实现 | 能否接受慢路径，或改写图 |

**效果：** 图拆分（GE）按引擎切开——见 [09](./09-backend-ge.md)。

## 3. 存储层次与 DMA

### 3.1 为什么分层

```text
容量 ↑        延迟 ↑、能效往往 ↓
片外 HBM/DDR  ──────────────
片上大缓存/ L2 …
片上小缓冲 UB/L1 …
寄存器
计算单元
```

片上小而快，片外大而慢。  
**每一次多写回片外，都可能变成瓶颈。**

### 3.2 DMA 怎样工作（直觉）

```text
计算正在用缓冲 A
DMA 同时把下一块数据搬进缓冲 B
换块 → 计算继续，尽量不闲等
```

这就是大纲 **Memory latency hiding**：用并行搬运藏延迟。

### 3.3 效果 → 对软件意味着什么

| 硬件事实 | 软件/编译对策 |
|---|---|
| 片上有限 | 内存复用、分组调度（原 LayerGroup 思想） |
| 写回贵 | **算子融合** 让中间结果留在片上 |
| 搬运可重叠 | 双缓冲、多 stream |
| 多核 | 图切分与并行调度 |

### 3.4 用在哪

- 解释「为什么融合能加速」  
- 读 profiling：算满还是搬满  
- 理解 ATC 文档里的 UB 融合等选项（代际有差异）

## 4. 和软件栈的接口

```text
模型图
  → ATC/GE：决定 op 落哪个引擎、如何融合、如何分配地址与 stream
  → om：把规划结果固化
  → 运行时按 task 执行，DMA 与 Core 按计划重叠
```

你不手写每条 DMA，但 **你改图/量化/AOE，就是在改这张计划表的输入**。
