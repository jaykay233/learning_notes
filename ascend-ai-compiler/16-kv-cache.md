# 16 · KV Cache 的 NPU 管理机制

> 原课：显存瓶颈与 KV 复用。

---

## 1. 为什么 KV Cache 是一等公民

自回归 decode：第 \(t\) 步需要过去所有位置的 K、V。  
若每步重算历史：算力爆炸。  
于是 **缓存** 历史 K/V——代价是：

```text
占用 ∝ 层数 × KV头数 × 序列长 × 头维 × dtype
```

序列一长，先撞上 **内存容量**，再撞上 **每步搬运带宽**。

---

## 2. 怎样管理（概念实现）

Runtime 要回答：

| 问题 | 为什么重要 |
|---|---|
| 存在哪 | HBM 布局影响吞吐 |
| 如何增长 | 预分配 max_len vs 动态分页 |
| 多请求 | batch 对齐、碎片、抢占 |
| 会话结束 | 释放/复用池，防泄漏 |

具体 API 随 MindIE/引擎变化；抓住 **容量模型 + 生命周期**。

**分页 KV（思想）：** 像虚拟内存，按块分配，减少「按 max_len 预留」的浪费。

---

## 3. 效果与算法侧分工

| 侧 | 手段 | 效果 |
|---|---|---|
| 结构 | GQA/MLA/稀疏 Attention | 少存、少算 |
| Runtime | 分页、池化、连续 batch | 同样结构下装更长/更多路 |
| 量化 | KV 也能量化（进阶） | 再省一档内存 |
