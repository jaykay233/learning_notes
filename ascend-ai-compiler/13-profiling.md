# 13 · 性能分析工具（Profiling）

> 原课：定位算子耗时与带宽利用率。

---

## 1. 为什么必须 Profile

「om 能跑」只说明正确性门槛过了。  
性能是另一维度：**慢在算、搬、还是主机同步**——猜想很容易错，要用数据。

---

## 2. 瓶颈类型（怎样解读）

| 类型 | 为什么出现 | 你可能采取的动作 |
|---|---|---|
| 计算受限 | Cube/Vector 时间高 | 换实现、AOE OPAT、检查是否真走 INT8 |
| 带宽受限 | 搬运/等待高 | 融合、量化、减写回、查 shape 是否过大 |
| 启动开销 | 一串碎 op | 融合、减少 host 同步 |
| Host 同步 | 过细 API、频繁 H2D | 批处理、流水（Lab5） |

工具名随 CANN/MindStudio 版本变；**读图的方法不变**。

---

## 3. 闭环（用在哪）

```text
Profile → 提出假设 → 改图/量化/AOE/流水
       → 再 Profile → 对比前后
```

与 [10](./10-memory-schedule-aoe.md)、[11](./11-int8-quant-math.md) 形成「性能工程」三角。
