# 06 · 开发环境搭建（昇腾版）

> 原课：WSL2+Docker+NPU 工具链 → 改为 **Linux / 官方 Docker / 昇腾云 + CANN**。

---

## 0. 为什么环境要单独成章

AI 编译器课一半的坑是：**驱动、CANN、**`soc_version`**、权限** 不一致，被误当成「理论没学懂」。  
先把「能看见卡、能跑 atc」变成可重复状态，后面 Lab 才有意义。

---

## 1. 目标环境长什么样

### 1.1 为什么要这些组件


| 组件                  | 为什么需要       | 缺了会怎样              |
| ------------------- | ----------- | ------------------ |
| 昇腾设备或云开发机           | 真实执行与部分调优   | 只能纸上谈兵 / 无法 AOE 实测 |
| 驱动+固件               | 内核与硬件对话     | `npu-smi` 都没有      |
| **CANN**            | ATC、运行时、AOE | 无法转 om             |
| msame / AscendCL 样例 | 验证 om       | 「转出来了但不会跑」         |
| Docker（可选）          | 锁依赖版本       | 本机 Python/系统库冲突    |




### 1.2 和原课 WSL2 的差别

原课常：Windows + WSL2 映射开发板。  
昇腾更常见：**服务器 PCIe 卡** 或 **云上 Atlas**。Windows 可做 SSH 客户端；编译建议在 Linux 侧。

---



## 2. 怎样搭建（推荐顺序）

```text
1. 确认 OS 与芯片型号（决定 soc_version）
2. 装驱动 → 装匹配版本的 CANN（看官方版本矩阵！）
3. source set_env 一类脚本
4. npu-smi / 等价工具看卡
5. which atc；跑官方最小样例
6. （可选）Docker：按社区镜像挂载设备节点
```

**为什么必须盯版本矩阵：** CANN 8.x 与驱动、与 om 不混用；混用表现为莫名失败，极难查。

| 用途              | 环境                   | 为什么         |

| Lab1 `mlir-opt` | 普通 Linux + LLVM/MLIR | **不需要** NPU |
